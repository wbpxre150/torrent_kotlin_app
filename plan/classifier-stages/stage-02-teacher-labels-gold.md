# Stage 2: Teacher labels and gold set

> Implement via `/dev` (dev-workflow) with this file as the task prompt.
> **Target repo: `~/apps/classifier-model`**. Design: `plan/classifier.md` §6 (training pipeline).

## ⚠ HARD CONSTRAINT — teacher LLM runs are done by the parent session directly

Any request that sends torrent data to the llama.cpp teacher (`http://192.168.0.24:8081/v1`, aliases
`FASTx1`/`FASTx2`/`SLOW`) is issued **by the parent session itself** (e.g. running `cm label` / `cm gold`
via bash once the implementer has committed them). Implementer and explorer subagents may write and unit-test
the labelling code but must **never execute the labelling loop, probes, or gold-prelabel passes** against the
real endpoint. The `/dev` parent therefore owns: the 120k overnight run, any teacher probe, and both gold
pre-labelling passes.

## Goal

Training labels plus a trusted evaluation set.

## Depends on

Stage 0 (120k sample + 3k gold candidates) and Stage 1 (tparse hints in the prompt — waiting is preferred;
name-only prompts give weaker `tv_kind` labels).

## Facts

- Teacher: `FASTx1` (Ornith-1.5-35B-A3B Q6_K, parallel 1), thinking off, `json_schema` output.
  Probe 2026-10-14: ~3.5 items/s, ~27 output tok/item. Budget: 100k ≈ 8 h, 300k ≈ 24 h at one slot.
- The server is shared: one request in flight by default (`config/labeler.toml` already pins this).
- Always send `chat_template_kwargs: {enable_thinking: false}` plus a `json_schema` response_format.
- Teacher gap found in the probe: `tv_kind` guesses without a file list are unreliable — prompts must
  include ≤ 12 filenames per item.
- `data/gold/` is hand-reviewed and frozen; never overwrite it with model output.

## Scope

1. `cm label` (implementer writes it; parent runs it):
   - Batches of 20; prompt `prompts/label_v1.md`; each item = name, size, n_files, ≤ 12 filenames,
     tparse hints.
   - `json_schema` from the taxonomy, thinking off, FASTx1, one request in flight.
   - Resumable (skips ids already labelled). Records model and prompt version.
   - Retries with backoff. Rejects rows that fail the schema or are missing an `i`.
2. Parent runs the 120k sample overnight (about 10 h).
3. `cm gold`:
   - Parent pre-labels the 3k gold candidates with **two** passes (FASTx1, plus `SLOW` with thinking on,
     run during a quiet window).
   - A review CSV or TUI that puts disagreements first.
   - **The user reviews ≥ 1,500 rows** (about 2–3 h), producing `data/gold/gold_v1.jsonl`, which is then frozen.
4. `cm evaluate`: teacher accuracy vs gold (targets: adult precision and recall ≥ 0.97, category ≥ 0.90;
   if missed, iterate the prompt to v2 and re-run the affected labels — the parent runs any re-label pass)
   plus the keyword-baseline scores from Stage 0.

## Build / validate

- `uv run pytest` (unit tests for batching, resume, schema rejection — against a mock endpoint, not the
  real teacher).

## Exit criteria

1. ≥ 100k labelled rows in `data/labels/`; < 1% schema failures (report the number).
2. Gold set reviewed by the user (≥ 1,500 rows) and frozen at `data/gold/gold_v1.jsonl`.
3. `cm evaluate` reports teacher accuracy vs gold (adult P/R ≥ 0.97, category ≥ 0.90) and the
   keyword-baseline scores; if targets were missed, a prompt v2 exists and was iterated by the parent.
4. All teacher traffic was generated by the parent session, not subagents.
5. `uv run pytest` passes.
